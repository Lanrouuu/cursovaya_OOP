# Вопросы и ответы для защиты курсовой работы TradeAds

## Общие вопросы об архитектуре

**— Какой архитектурный паттерн использован в проекте?**

MVVM (Model-View-ViewModel) в сочетании с трёхслойной архитектурой: данные → бизнес-логика → представление. View содержит только XAML-разметку. ViewModel хранит состояние экрана и команды, обращается к сервисам. Сервисы реализуют правила приложения и работают через репозитории. Репозитории изолируют доступ к Entity Framework.

**— Зачем использовать MVVM вместо code-behind?**

Code-behind жёстко связывает логику с конкретным окном — её нельзя переиспользовать или протестировать изолированно. MVVM позволяет ViewModel работать независимо от View: все команды и данные доступны без создания UI. Это снижает сложность при изменении интерфейса: если нужно переделать карточку объявления, ViewModel не трогается.

**— Что такое INotifyPropertyChanged и зачем он нужен?**

Интерфейс с одним событием `PropertyChanged`. Когда ViewModel меняет свойство и вызывает это событие, WPF-биндинг получает уведомление и обновляет только привязанные элементы UI. Без этого интерфейса значения в окне не обновлялись бы при изменении данных. Реализован в базовом классе `ViewModelBase` — все ViewModel наследуют его.

**— Что такое ICommand / RelayCommand?**

`ICommand` — стандартный интерфейс WPF для команд кнопок. `RelayCommand` — собственная реализация: принимает `Action` (что делать) и `Func<bool>` (когда кнопка активна). Это позволяет привязывать любой метод ViewModel к кнопке через `{Binding SomeCommand}` без event handler в code-behind.

## База данных и Entity Framework

**— Почему выбран Entity Framework Code First?**

Code First позволяет описывать структуру базы прямо в C#-классах и получать миграции автоматически. Нет необходимости писать SQL для создания таблиц — достаточно изменить класс модели и выполнить `dotnet ef migrations add`. Это ускоряет разработку и держит схему БД синхронизированной с кодом.

**— Что такое миграция и зачем она нужна?**

Миграция — снимок изменений в структуре таблиц. При добавлении нового поля (например, `ExpiresAt`) создаётся миграция с методами `Up()` (применить) и `Down()` (откатить). При следующем запуске приложение вызывает `Database.MigrateAsync()` и применяет все непримечённые миграции. В проекте две миграции: `InitialCreate` и `AddPerformanceAndFeatures`.

**— Как устроены связи в базе данных?**

- `Users` → `Advertisements`: один-ко-многим, `DeleteBehavior.Restrict` — удалить пользователя с объявлениями нельзя, это защищает целостность данных.
- `Categories` → `Advertisements`: аналогично, `Restrict` — нельзя удалить категорию, если к ней привязаны объявления.
- `Users` → `FavoriteAdvertisements`: CASCADE — при удалении пользователя его список избранного удаляется автоматически.
- `Advertisements` → `FavoriteAdvertisements`: CASCADE — при удалении объявления его запись в избранном исчезает.

**— Зачем Repository и Unit of Work?**

Repository абстрагирует доступ к конкретной таблице: сервис вызывает `_uow.Advertisements.GetByIdWithDetailsAsync(id)`, не зная про `DbContext`. Unit of Work объединяет несколько репозиториев и один общий `SaveChangesAsync()`. Это гарантирует, что несколько изменений в одной бизнес-операции либо сохраняются вместе, либо не сохраняются вовсе.

**— Что такое `IQueryable` и почему он важен?**

`IQueryable` — ленивый запрос, который ещё не пошёл в БД. Метод `QueryWithDetails()` возвращает `IQueryable<Advertisement>` с уже добавленными `Include`. Сервис дополняет запрос условиями `Where`, а `ToListAsync()` в конце отправляет один SQL-запрос со всеми фильтрами. Альтернатива — загружать все записи в память и фильтровать в C# — была бы на порядки медленнее.

**— Как работает пагинация?**

`GetPagedAsync` сначала вызывает `CountAsync()` (отдельный `SELECT COUNT`), затем `Skip((page-1) * pageSize).Take(pageSize).ToListAsync()`. Результат упаковывается в `PagedResult<T>` с полями `TotalCount`, `TotalPages`, `HasPrevious`, `HasNext`. ViewModel управляет `CurrentPage` и вызывает `LoadPageAsync()` при смене страницы.

## Безопасность

**— Как хранятся пароли?**

Пароль никогда не хранится в открытом виде. При регистрации вызывается `PasswordService.HashPassword(password)`, который вычисляет SHA-256 хэш и сохраняет его в поле `PasswordHash`. При авторизации хэш введённого пароля сравнивается с хэшем из базы. Получить исходный пароль из хэша вычислительно невозможно.

**— Как защищены поля ввода от некорректных данных?**

Многоуровневая валидация: в ViewModel (до отправки формы), в сервисах (до обращения к репозиторию), на уровне EF (длины строк через `HasMaxLength` и `Required`). Дополнительно: все строки проходят `.Trim()`, email проверяется через регулярное выражение, телефон — через regex, цена проверяется на диапазон 0–999 999 999.

**— Почему `PasswordBox` а не `TextBox` для паролей?**

`TextBox` хранит значение в памяти как обычную строку, которая может попасть в дамп памяти процесса. `PasswordBox` хранит пароль в `SecureString`. Для MVVM-биндинга реализован `PasswordBoxHelper` (attached property), который синхронизирует `PasswordBox.Password` с ViewModel через событие `PasswordChanged`, не раскрывая строку в XAML-биндинге.

## Функциональность

**— Как работает поиск и фильтрация?**

`AdvertisementsViewModel` при изменении любого поля фильтра вызывает `ReloadAfterChange()`, которая сбрасывает страницу на 1 и вызывает `LoadPageAsync()`. Метод собирает `AdvertisementFilter` и передаёт в `AdvertisementService.GetPagedAsync()`. Там строится `IQueryable`, к которому последовательно добавляются условия `Where` для каждого непустого фильтра. SQL выполняется один раз при `ToListAsync()`.

**— Как работает Undo/Redo?**

`UndoRedoService` хранит два стека: действия для отмены и для повтора. При добавлении/редактировании/удалении объявления в стек кладётся объект, реализующий `IUndoRedoAction` с методами `UndoAsync()` и `RedoAsync()`. Каждый объект знает, как восстановить предыдущее состояние (например, `DeletedAdvertisementAction.UndoAsync()` возвращает статус `Active`). Событие `StateChanged` обновляет состояние кнопок в шапке.

**— Как работает система избранного?**

`FavoriteService.ToggleAsync(userId, advertisementId)` проверяет, есть ли запись в `FavoriteAdvertisements`. Если есть — удаляет и возвращает `false`. Если нет — добавляет и возвращает `true`. В ViewModel каждое объявление обёрнуто в `AdvertisementCardViewModel` с собственным свойством `IsFavorite` и счётчиком `FavoritesCount`. При toggle эти свойства обновляются локально — перезагрузки страницы не происходит.

**— Как работает автоматическое истечение объявлений?**

При создании объявления устанавливается `ExpiresAt = DateTime.Now.AddDays(30)`. При каждом открытии списка вызывается `ExpireOverdueAsync()` — LINQ-запрос находит все активные объявления с `ExpiresAt < DateTime.Now` и устанавливает им `Status = Hidden`. Отдельный метод `NotifyExpiringAsync()` находит объявления, у которых `ExpiresAt.Date == DateTime.Today.AddDays(3)`, и отправляет email-предупреждение.

**— Как работает смена темы?**

`ThemeService.ApplyTheme(themeName)` находит ResourceDictionary темы (по имени файла) в `Application.Current.Resources.MergedDictionaries`, удаляет старый и добавляет новый. Так как стили используют `{DynamicResource}`, все элементы UI немедленно перекрашиваются без перезапуска. Системная тема читается из реестра Windows (`AppsUseLightTheme`) при первом запуске.

**— Как работает навигация без Frame?**

`NavigationService.Navigate(viewModel)` устанавливает свойство `CurrentViewModel` в `MainViewModel`. WPF-биндинг в `MainWindow.xaml` обновляет `ContentControl.Content`. DataTemplates в ресурсах `MainWindow` сопоставляют тип ViewModel с нужным View. WPF автоматически создаёт и отображает нужный View. Это устраняет зависимость от `Frame`/`Page` и даёт полный контроль над жизненным циклом ViewModel.

**— Как реализована локализация?**

Два словаря ResourceDictionary: `Strings.ru-RU.xaml` и `Strings.en-US.xaml`. Каждый содержит ~107 строк с одинаковыми ключами. В XAML — `{DynamicResource KeyName}`. `LocalizationService.ApplyLanguage()` заменяет текущий словарь языка на новый. `EnumToStringConverter` локализует enum-значения через `CultureInfo.CurrentUICulture`.

**— Как работает Drag & Drop для изображений?**

В `AddEditAdvertisementView.xaml` граница превью имеет `AllowDrop="True"`. Обработчики `DragOver` и `Drop` прописаны в code-behind (минимальный code-behind оправдан — это чисто UI-операция). `DragOver` проверяет, что передаются файлы, и устанавливает эффект `Copy`. `Drop` извлекает путь первого файла и вызывает `vm.ApplyDroppedImage(path)`. ViewModel в `ImageService` проверяет расширение и копирует файл в `Assets/UserImages/` с GUID-именем.

**— Как работает экспорт в CSV?**

`ExportService` открывает `SaveFileDialog`, создаёт `StreamWriter` с кодировкой UTF-8 и записывает строки через разделитель `;`. Поля, содержащие `;`, `"` или перенос строки, оборачиваются в двойные кавычки, внутренние кавычки удваиваются — это стандартный RFC 4180. Библиотек не требуется: только `System.IO`.

## Email-уведомления

**— Как настроены email-уведомления?**

Через `appsettings.json` секция `Smtp`: хост, порт, email отправителя, пароль. `EmailService` использует `System.Net.Mail.SmtpClient`. Если поле `From` начинается с `your-` (значение по умолчанию), письма не отправляются — приложение работает без ошибки. Это позволяет запустить проект без настройки SMTP.

**— Какие события вызывают отправку писем?**

| Событие | Получатель |
|---------|-----------|
| Регистрация | Новый пользователь — приветствие |
| Блокировка аккаунта | Заблокированный пользователь |
| Разблокировка аккаунта | Пользователь |
| Блокировка объявления администратором | Автор объявления |
| Активация объявления администратором | Автор объявления |
| 3 дня до истечения объявления | Автор объявления |

## Типовые вопросы на защите

**— В чём разница между `async/await` и синхронным вызовом?**

`async/await` освобождает поток UI на время ожидания ответа от базы данных. Без него при загрузке 100 объявлений интерфейс замерзал бы на время запроса. С `await` UI остаётся отзывчивым: пользователь может взаимодействовать с приложением, пока данные загружаются.

**— Почему мягкое удаление (Status=Deleted) вместо физического?**

Физическое удаление необратимо и нарушает ссылочную целостность (например, логи могут ссылаться на удалённое объявление). Мягкое удаление сохраняет запись в БД, но исключает её из выборки. Поддерживается Undo: действие `DeletedAdvertisementAction.UndoAsync()` просто возвращает статус обратно в `Active`.

**— Что будет, если два пользователя одновременно нажмут «Продлить» одно объявление?**

Entity Framework по умолчанию использует оптимистичную конкурентность. Оба запроса выполнятся — операция идемпотентна (оба просто установят `ExpiresAt = DateTime.Now.AddDays(30)`), результат будет корректным. Для транзакционных операций (например, при подтверждении заказа) применялся бы `BeginTransactionAsync()`, но для продления это избыточно.

**— Зачем `DbInitializer`?**

При первом запуске таблицы пусты. `DbInitializer.InitializeAsync()` проверяет пустоту таблиц и добавляет тестовые данные: администратора, пользователя, 7 категорий и несколько объявлений. Это позволяет сразу работать с приложением без ручного заполнения БД.

**— Что такое `FavoritesCount` и почему он не в базе?**

Это вычисляемое свойство C#:
```csharp
public int FavoritesCount => FavoriteAdvertisements.Count;
```
Когда `QueryWithDetails()` включает `.Include(x => x.FavoriteAdvertisements)`, EF загружает коллекцию связанных записей. Свойство просто считает их количество. Хранить счётчик в отдельном поле было бы избыточно — пришлось бы следить за синхронизацией при каждом добавлении/удалении из избранного.
